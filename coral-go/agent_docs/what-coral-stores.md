# What Coral stores on this computer

Coral keeps its data in one folder, `<data dir>` (`~/.coral` unless `CORAL_DATA_DIR` says otherwise). The files in the table are readable only by you (file mode 0600, in a 0700 folder). This page says what is kept, how long, whether it is cleaned of secrets, and where to change it. Coral does not send this data anywhere on its own; what you deliberately share is the exception — an artifact link, or a file you attach to a cross-team message bound for another Coral. The last section says what reaches Coral Hub.

| What | Kept | Cleaned of secrets? | To change it |
|---|---|---|---|
| **Terminal logs** (`<data dir>/logs/<agent>_coral_<id>.log`: what an agent's terminal showed) | Kept: Coral does not delete them, also when an agent is killed, slept or archived, on either terminal backend. | Raw on disk. Redacted when Coral Hub serves them (the connector does it); the dashboard on this computer shows them as the terminal showed them. | Settings > Storage > **Terminal logs** deletes the logs of agents that have **ended** (their count and size are shown first, you confirm, it is never automatic; the log of a live, sleeping or archived agent is never touched). Or delete a log's file in `<data dir>/logs`. |
| **Board messages and tasks** (`messageboard.db`) | Until you delete the message or the board. Coral never ages them out. | Redacted where Coral's secret rules apply (task text, chat views); not everywhere. | Delete a message (its ×) or the board. |
| **Sessions, search index, usage** (`sessions.db`, which also holds the search index) | Kept. Events, call metrics and token rollups have their own retention. | Where Coral's secret rules apply; not everywhere. | No single setting; see [settings-system.md](settings-system.md). |
| **Saved messages** (table `saved_messages` in `sessions.db`: the Operator's bookmarks on chat and board messages, with a one-line snippet) | Until you remove them (the Saved list's **Remove**). | The snippet is redacted when it is saved. | The Saved tab in the dashboard, or see [saved-messages.md](saved-messages.md). Its message keys use the secret in the next row. |
| **Message key secret** (`<data dir>/.message_key_secret`: 32 random bytes in hex, mode 0600; keys the Save for later message keys, so a key cannot be used to test a guess at a redacted message) | Until you delete it, which makes every saved message not found (a new one is made at the next use). | It is a random secret, not Coral data; never sent anywhere and not part of a Coral Hub reply. | Nothing to set; see [saved-messages.md](saved-messages.md#the-message-key). |
| **Uploads** (`<data dir>/uploads/`: images you paste or attach to a chat; each also has a copy in the artifact store, and the agent is given its `coral://artifacts/...` link, not the path) | 30 days or 1 GB, whichever comes first. Read by the agent you paste it into and the other agents on its board, and anyone who can open the dashboard on this computer; through Coral Hub only the account this computer is linked to (every artifact there is the owner's alone). The agent's own command-line tool sends the image to its model provider as part of the conversation. | No: metadata is dropped from a JPEG, PNG or GIF, but the picture is not scanned, so a screenshot keeps whatever it showed. | `uploads_retention_days` (1 to 365, default 30) and `uploads_max_mb` (50 to 102400, default 1024), see [settings-system.md](settings-system.md#upload-an-image). Delete an upload by its API. Remove one image's shared copy with the × on its thumbnail in the chat. |
| **Artifacts** (`<data dir>/artifacts/objects/`: files and reports agents publish) | No age limit by default. A store cap you can set. Files received from other teams and Corals have their own cap, 2 GiB by default (Settings > Storage, Received files limit); that includes received files whose message never came, which Settings lists so you can delete them. | Images lose their metadata; other bytes are stored exactly as uploaded and served exactly (artifact bytes are not redacted). | Settings: **Artifact store limit (GiB)** and **Automatic cleanup (days)** (0 is off), and the Operator's **Delete**. See [artifacts.md](artifacts.md#freeing-space-the-operator). |
| **Launch files** (the prompt, instructions and settings Coral writes to start an agent) | In `<data dir>/tmp`, removed when the agent ends. Ones a crash left behind are removed at a later start once they are over a day old and no running agent uses them (files in the old system temp folder only if this Coral saw their session end). | No: a prompt file holds the whole launch prompt. | Nothing to set. |
| **Input debug log** (`input-debug.log`: what Coral typed into agents' terminals) | Off by default. When on: at most 5 MiB plus one older copy. | **No.** It holds typed text, which may include secrets. | Settings: **Log terminal input (debug)**, then **Delete the log** once it is off. See [troubleshooting.md](troubleshooting.md#seeing-exactly-what-coral-types-into-an-agents-terminal). |
| **Coral's own logs** (`coral.log`, `tray.log`, `app.log`) | Rotated at 20 MB, five older copies each. | `coral.log`: yes (secret rules are logged at startup). | Delete the files. |

## Things to know

- **A Kill keeps the terminal log.** Killing an agent ends it; its terminal log stays in `<data dir>/logs`, as it does for Sleep and Archive. Every Kill confirmation says so. To remove a log, delete its file.
- **Terminal logs are the biggest and the most revealing.** They record what the terminal showed, secrets included. Coral Hub gets them redacted; the dashboard on this computer shows them as the terminal showed them. Treat `<data dir>/logs` like the agents' own terminals.
- **Board history is a product choice.** Coral keeps your board messages and tasks so a team has a memory; nothing removes them unless you do.
- **Artifacts are served byte for byte.** Coral cannot hide a token in an artifact: redact a log or a screenshot before you upload it (see [artifacts.md](artifacts.md#limits-images-and-deleting)).
- **The agent CLIs (Claude, Codex and the others) keep their own transcripts** in their own folders. Coral does not manage those.
- **The Coral app's browser profile is outside `<data dir>`, and on Windows it stays on this computer.** The Coral app (`coral-app`, the dashboard in its own window) keeps its WebView2 profile, with the dashboard's sign-in cookie (24 hours, or 30 days if you chose to stay signed in), cache and local storage, in `%LOCALAPPDATA%\Coral\WebView2\EBWebView` (WebView2 adds the `EBWebView` folder). That is the Local folder, which does not roam, so it is not copied to a profile server. Coral sets `WEBVIEW2_USER_DATA_FOLDER` to it before the window opens; a folder you or an administrator already put in that variable is left alone. The cookie is encrypted with your Windows account (DPAPI), and the folder is yours. Earlier versions kept the profile in `%APPDATA%\coral-app.exe\EBWebView` (the Roaming folder); the app no longer uses it, so you sign in once more after updating, and you can delete that old folder. To drop the sign-in, close the app and delete the `WebView2` folder (the app asks Coral for a new sign-in link when it starts). The dashboard in your own browser is not affected: its cookie is in that browser's profile.
- **Other files:** per-session board state (`board_state_*.json`, no message text), the knowledge notes an agent distills (`agent_knowledge/`), and a few small caches. They are kept until you delete them.

## What reaches Coral Hub

Only what Coral's redacting connector sends: View-tier replies and the redacted terminal and agent-list streams. A raw file on this page is never sent to Coral Hub. Two things to know: **artifact downloads are served byte for byte** (they are exempt from redaction on purpose, so an artifact you share can be opened and is shown exactly), and **uploads are not served back through Coral Hub**. Whatever you see through Coral Hub that is not an artifact has been redacted on this computer first. A file you attach to a cross-team message addressed to another Coral is also sent through Coral Hub, in memory (the hub does not store it), byte for byte — not redacted, but scanned for secrets first, and a send whose file looks like it holds a token or key is refused (`attach_secret`). See [hub.md](hub.md) and [cross-team.md](cross-team.md#attaching-artifacts).

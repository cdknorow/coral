# Saved for later

The Operator can bookmark a message of an agent's chat or of a board with **Save for later**, and click the bookmark in the **Saved** list to go back to that point of the conversation (#4510). The bookmarks are the Operator's own notes: an agent's token is refused on every route below (`403 operator_only`), and nothing an agent does adds one.

## In the dashboard

- A bookmark button (an inline SVG, filled and in the accent colour when saved) one slot to the left of **Copy** on each message of an agent's Chat view, in History too, and in each board message's header. It shows on hover or keyboard focus, always while saved, and always on touch, where it and Copy are 44 px targets. Its name is "Save for later" or "Remove from saved" (`aria-pressed` says which). Saving shows a toast "Saved." with **View saved**; removing shows "Removed from saved." with **Undo**.
- **Saved** is a tab of the right sidebar, which is on every page: beside Files, Tasks and the others on an agent's page, beside Subscribers, Team artifacts and Tasks on a board, and the only tab in Chats and on the other pages (a bookmark with the number open). The list stays in view while the main view shows something else. Each kind of page (an agent, a board, Chats, the rest) remembers whether its sidebar is open, how wide it is and which tab it was on; an agent's page starts open, a board when the window is wide enough to leave its messages about 560 px (about 1300 px of window), Chats and the other pages closed. The sidebar's Saved tab is opened by its own tab, by the toast's **View saved** link and by the jump bar's **Back to Saved**, with the focus moved into the list; its number is the open items of the page's scope (below). The **Saved** button in the top bar is not the sidebar's: it is the Inbox's (next item). On a phone the tab is in the side panel overlay, which gives way to the conversation when an item is opened. The tab has an **Open** and a **Done** list, newest saved first. An item shows the agent or board and a chip (**Agent**, **Board**, **Ended agent** or **Gone**), a two-line snippet, when it was said and when it was saved, and **Open chat** / **Open board** / **Open in Chats**, **Done** (**Reopen** in the Done list) and **Remove**. Results are announced politely ("Marked done", "Removed from saved").
- **Everything is in the Inbox (#4811).** Where the scope is all (home, Chats, Workflows, Jobs, Analytics, Docs, Servers: any page with no agent or team open), Saved is not a right-hand panel. The **Inbox** tab, on every Coral (right after Agents on a Coral with no Servers tab; on a phone it is in the view dropdown), is a full-screen page built by the dashboard, tabbed as the hub's `/inbox` page is (#5126): a header, then two tabs, one panel on screen at a time (arrow keys, Home and End move between the tabs; the last tab chosen is kept in this browser and survives a reload; the page opens on Needs you the first time): **Needs you** (the agents waiting for input, from the live list's `waiting_for_input`, each a button that opens that agent) and **Saved for later** (every item of every server in hub mode, with the shared bar, the **Open** and **Done** tabs). The tab's number is how many agents wait. The top bar's bookmark (a bookmark with a number; on a phone at large text, where the bar has no room, an entry of the settings menu with its number) ALWAYS opens the Inbox on its Saved for later tab, everything's list, on every page, an agent's and a team's too (#4905), and its number is the open items of everything (every online server's in hub mode), whatever page is on screen. It is pressed while the Inbox shows; pressing it again, or **Escape**, goes back to the page it was opened from. Where the hub serves the dashboard the Inbox tab is still the hub's `/inbox` page in a frame (#4718). The right sidebar has no Saved tab on a page where the scope is all, and a page that has no other tab (Chats with no chat open, the rest) has no sidebar at all. The Inbox writes no address of its own: Back is the browser's, and **Escape** (when the key is not meant for a field or a menu) or a second press of the bookmark leaves it for the page it was opened from. **Open chat** and **Open board** go to that agent or board, and the jump bar's **Back to Saved** returns to the Inbox. The Saved list is the same one as the sidebar's (one component: saved.js moves it into the Inbox and back), so nothing differs but where it is shown.
- **The list is of where it is opened from (#4792).** In an agent's page (right-hand sidebar) it shows that agent's own bookmarks: its chat, and the board messages it wrote on its team's board. In a team's page (the team opened from the agent list, or its board) it shows the team's: its board's messages and the chats of its agents. On home and on the other pages it shows everything, in the Inbox above. A heading says which ("Saved: QA Engineer", "Saved: coral-go-team", "Saved: all"), the **Open** and **Done** numbers are of that scope, and so is the number on the Saved tab (the top bar's button counts everything). The scope follows the page: choosing another agent or team while the list is open reads it again, and a conversation filter left from the last scope is cleared. In hub mode an agent's or team's scope asks only the server it is on. The server does the matching (`team`, `agent` and `author` below), so nothing is filtered over a capped list. A bookmark saved before this was kept belongs to its board's team (a board message) or to no team (an agent's chat): the chat still shows in its agent's own list and in everything, but not in its team's; a board message's author is read from the board the first time an agent's list asks, once.
- Clicking **Open** goes to the message and leaves the Saved tab where it is: an agent that is running opens in its Chat view and pages up until the message is found; an agent that has ended opens in Chats (History) at the message; a board opens and loads older messages as the board's search does. The page you land on shows its sidebar as you last left it (a board opens on Subscribers, say), so the bar's **Back to Saved** and the top bar's button bring the list back there. The message is outlined, tagged **Saved** and takes the focus, and a slim bar above the conversation says so with **Back to Saved**.
- When the tab is shown each item is checked: a message the transcript no longer has, a conversation whose transcript is gone, or a board message that was deleted is marked **Gone**, says why, keeps its snippet and can only be removed.
- **Hub mode (a Coral running with `--hub` over registered servers):** messages of the live agents and the boards of a registered server have the same button; the bookmark is kept on THAT server (the hub's proxy sends the save to its `/api/saved`, with the hub's key, which the server treats as the Operator's, never an agent's), so each server keeps its own items. The Saved tab merges this computer's list with every online registered server's, newest saved first, and each item names its server; the top bar's number adds them. A server that does not answer shows one line ("<server> did not answer, so its saved messages are not shown") and its items are left out until it does. **Open** goes to the remote agent (paging up to the message) or board through the proxy; **Done**, **Reopen** and **Remove** go to the item's own server. An agent that has ended on a registered server is kept but cannot be opened from the hub (Chats shows only this computer's history): its item says so and can be marked done or removed.
- Not in this version: Coral Hub's own dashboard has no Save button yet (the roll-up across servers on Coral Hub is being agreed with coral-hub).

## The message key

A chat message is found again by a key the server adds to each message it returns, in `GET /api/sessions/live/{name}/chat` and `GET /api/sessions/history/{id}`: `key`, the first 20 hex characters of an HMAC-SHA256 of the message's type, timestamp, text (`content` or `text`) and, for a tool call or result, the tool's name and id, keyed with a secret that belongs to this installation (`<data dir>/.message_key_secret`, 32 random bytes in hex, mode 0600, made at first use and kept: a key must survive a restart). The secret is what keeps the key from being a way to test guesses: through Coral Hub at View the text of a reply is redacted but its key is not, and `find_key` answers whether a message exists, so a plain hash of the text would let a viewer check a guess for a redacted password offline. If the file cannot be read or made, a secret lasting until the next restart is used and a warning is logged. The same message has the same key after a reload, a poll, another page size, and in History, so a bookmark survives them. Two messages that say the same thing at the same second share a key (the jump finds the first). A board message is its own id.

`GET .../chat?session_id=SID&find_key=KEY` and `GET /api/sessions/history/{id}?find_key=KEY` answer `{"found": bool, "index": n, "total": n}`: whether the transcript still has the message, and its index (the History view opens at `message_index`).

## API

All the routes answer only a person: the dashboard on this computer, the signed command line, or Coral Hub (the tunnel allows the list and the whole message at **View** and the changes at **Interact**: the bookmarks change no work). Through Coral Hub EVERY saved route is the **account this computer is linked to alone** (#5753, #5763): the list, the whole message, saving, marking done and removing; any other hub user, an Interact grantee included, gets `403 owner_only`. An agent's token and a token-less script get `403 operator_only`, a forged hub stamp `403 owner_only`.

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/saved?state=open\|done\|all&kind=agent\|board&conv=<session id or board>&q=<text>&sort=newest\|oldest&limit=N&team=<board>&agent=<session id>&author=<name>` | `{"items": [...], "open": n, "done": n, "total": n}`, newest saved first. `kind` and `conv` narrow it to one conversation; `q` (#4745) keeps the bookmarks whose title or snippet holds that text (a plain, case-insensitive substring, at most 200 characters, given once; `%` and `_` are ordinary characters); `sort=oldest` reverses the order; `limit` keeps the first N of that order (`limit=0`: only the counts, which the top bar's number asks for). `total` is how many bookmarks the filters and `q` match, whatever `limit`; `team` keeps one team's bookmarks (its board's messages and its agents' chats, #4792); `agent` keeps one agent's chat (its session id, or the session name for an ended agent), and with `team` and `author` (the name the agent writes under on that board) the board messages it wrote; `author` needs both, and each is given once, at most 300 characters. `open` and `done` count the bookmarks of that scope (all of them with none), whatever the other filters. Through Coral Hub the match is made on what the viewer sees, and a `q` holding a token, key or password is refused with a 400. |
| POST | `/api/saved` | Save `{kind, ref, key, agent_type, title, snippet, said_at, team, author}`. `ref` is the session id or the board; `team` is the board an agent was on (a board message's team is its own board), `author` who wrote a board message (the name the board shows); `key` the message key (20 hex characters for an agent, the message id for a board). Saving a saved message again answers the bookmark that exists. At most 2,000 are kept (`409`). |
| GET | `/api/saved/{id}/message` | The whole text of the bookmarked message (#5753): `{"text": "...", "partial": false, "reason": ""}`. The source is the STORED bookmark's (its kind, ref and key; nothing in the request names one): a board message by its board and id (an id of another board is not found), an agent's by its session and key in the transcript this computer holds. The text is redacted and cut to 64 KiB where no token is split: then `partial` is true and `reason` is `too_long`. `reason` is always there, empty when the whole text is. With no text, it is `gone` (the message no longer exists) or `not_reachable` (this computer holds no transcript of that agent, the bookmark's ref is not a session id, or the board could not be read). The reply is never cached (`Cache-Control: no-store`), like the list. `404` for an unknown bookmark. |
| PATCH | `/api/saved/{id}` | `{"done": true\|false}`. |
| DELETE | `/api/saved/{id}` | Remove. |

An item is `{id, kind, ref, key, agent_type, title, snippet, said_at, saved_at, done_at, team, author}`.

**The snippet is redacted when it is saved**, not only when it leaves the computer: Coral's secret rules replace a token in it with `[redacted token]`, it is cut to one line of at most 200 bytes where no token can be split, and text that cannot be checked is not kept. The bookmarks are in `sessions.db` (table `saved_messages`) and are kept until the Operator removes them.
